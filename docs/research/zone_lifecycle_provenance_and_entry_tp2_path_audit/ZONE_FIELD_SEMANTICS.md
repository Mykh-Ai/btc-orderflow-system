# Zone field semantics and historical cutoff audit

Scope: `market_monitor/zone_registry.py` as invoked by frozen `docs/research/open_trade_outcome_predictor_v1/snapshot_v2.py:149-167`; all times below are UTC labels on supplied minute or aggregated bars. Snapshot passes 1440 pre-cutoff minutes and no `registry_in`. Registry fields may be persisted by other callers that supply `registry_in` (`zone_registry.py:147-184`), but the frozen snapshot recomputes them. None of these fields is the lifecycle of the separately built significant aggregate.

| Field/event | Exact trigger, source and timestamp | Persistence and cutoff safety |
|---|---|---|
| `first_seen_at` / created | Registry copies liquidity-map `created_at`; map derives from structure level(s) and can merge source levels (`zone_registry.py:276-293`; `liquidity_zones.py:153-250`). It marks recognition/confirmation in this reconstruction, not the first historical price approach. | Fresh registry rows every Snapshot run; merge target keeps minimum `first_seen_at` (`zone_registry.py:423-455`). Safe only when structure input is pre-cutoff. |
| First approach | No dedicated `first_approach_at` field or assignment in registry; `APPROACHED` appears among carry statuses, but `_path_status` only returns ACTIVE, TOUCHED or CROSSED_UNCLASSIFIED (`zone_registry.py:86-93,584-606`; `rg -n 'APPROACHED|first_approach' market_monitor/zone_registry.py`). | **Missing** as a stable timestamp. Could not claim deterministic same-object approach history. |
| `status`, first touch / first cross | For BUY_SIDE, M1 `HiPrice >= lower` and `LowPrice <= upper` is touch; `HiPrice > outer upper` is cross. SELL_SIDE reverses outer-bound cross (`LowPrice < lower`). First qualifying supplied M1 bar supplies `last_touch_at`/`last_cross_at`; status becomes CROSSED_UNCLASSIFIED ahead of TOUCHED, then ACTIVE. `REACTED` overrides when consumption status is REACTED. `MERGED` and `EXPIRED` are separate transformations (`zone_registry.py:547-606,1199-1219,513-524`). | Recomputed in snapshot. `last_touch_at` is not strictly first touch; on no cross it is overwritten with current first touch on each run (`:559-567`). Helper has **FUTURE_LEAKAGE_RISK** if supplied future rows. |
| `consumption_status` | Starts FRESH; TESTED for touch/inside; SWEPT_ONCE for HTF sweep/acceptance or cross; REACTED for clean reaction; CONSUMED after 3 full wick-through bars for non-broad zones; CHOPPED_THROUGH after 3 alternating outside closes or 20 inside closes for non-broad zones, or two-sided broad chop plus thresholds and no clean reaction; EXPIRED after age >7 days unless exempt (`zone_registry.py:95-106,719-785,1199-1237`). Order of `if/elif` branches matters: HTF sweep or acceptance takes precedence over broad chop. | Recomputed from supplied M1/HTF feed in Snapshot; merges choose a precedence across members (`:1566-1581`). Not an immutable single-event tag. Cutoff-safe through caller only. |
| `active_forward`, `active_forward_role` | Role derives from inactive status/precision/consumption, local session source, M15 source, or broad behavior (`zone_registry.py:1668-1745`). Flag excludes AUDIT_ONLY, INACTIVE, local context roles, some M15 fresh roles, disallowed status, too-wide precision, and inactive consumption (`:1166-1196`). | Recomputed after lifecycle and expiry (`:578-579,1216-1217`). Role can change when source/history changes. Cutoff-safe through caller only. |
| `first_sweep_at`, `resweep_count` | On M1, a sweep is a false→true transition of `HiPrice > outer upper` for BUY_SIDE or `LowPrice < outer lower` for SELL_SIDE; first transition timestamp is `first_sweep_at`; resweep count is transition count minus one (`zone_registry.py:670-673,895-908`). A wick is sufficient; a close beyond is not required. | Prior first sweep survives if `registry_in` carried; otherwise recomputed from last 1440 M1 bars. `resweep_count` recalculates only supplied window, so older sweeps can be lost. Cutoff-safe through caller only. |
| `accepted_above_at`, `accepted_below_at` | For either side, M1 `ClosePrice > outer upper` or `< outer lower`; first **three consecutive closes** outside the same boundary. Timestamp is the **third** close (`zone_registry.py:101,653-658,674-675,1011-1017`). This is not a single penetration, a wick, or side-specific accepted direction. Separate HTF `htf_acceptance_count` uses three consecutive closes of the selected aggregated timeframe (`:925-982,995-1008`). | Recomputed from available M1/HTF bars, or earliest merged timestamp carried (`:479-485`). A boundary-changing merge may alter what the event means. Caller cutoff-safe; helpers **FUTURE_LEAKAGE_RISK**. |
| `failed_acceptance_count` | In side-specific direction only: BUY_SIDE close above upper, SELL_SIDE close below lower; runs of 1–2 closes (strictly less than 3) count as failed if one of next at most three M1 closes returns to/inside the crossed boundary (`zone_registry.py:1020-1051`). A run ending at the feed cutoff without return is not yet counted. | Recomputed from supplied M1 bars. A future return can change a prior run's classification if future data is passed; **FUTURE_LEAKAGE_RISK** in helper. |
| `rejection_without_sweep_count` | BUY_SIDE high reaches core lower but not beyond outer upper, then a later close below core lower; SELL_SIDE symmetric low/close (`zone_registry.py:1054-1079`). No dedicated timestamp. | Recomputed from supplied M1 bars; caller cutoff-safe only. |
| Return inside / re-entry through opposite boundary | Registry has no dedicated persisted event fields for these. Snapshot `_recent_cleared` checks **any** M1 close after accepted time within `[lower,upper]`, and any close through the opposite boundary; it exposes booleans only if a cleared registry row passes eligibility (`snapshot_v2.py:231-262`). | Deterministic for retained same registry row and clipped feed; older/filtered-out structure is absent. Helper **FUTURE_LEAKAGE_RISK** if `current` contains later rows. |
| `last_clean_reaction_at` | After first side-direction wick crossing, scan at most 31 M1 bars including crossing bar; require a close inside then a close away beyond opposite boundary (BUY_SIDE below lower, SELL_SIDE above upper). Timestamp is the final away close, not the initial wick or return. A previously REACTED/FLIPPED row instead returns stored touch/cross time (`zone_registry.py:1139-1163`; limit at `:100`). | Recomputed in Snapshot; with persisted input may retain an earlier value. Helper cutoff-safe only; a future away close could create this event. |
| `consumed_at`, `consumption_reason` | For non-broad zones, timestamp of third full wick-through, third alternating outside close, or twentieth inside close; reason names threshold. Broad two-sided chop uses corresponding threshold. Expiry uses last updated/seen timestamp and `MAX_ZONE_AGE_DAYS_EXCEEDED` (`zone_registry.py:719-780,865-892,1199-1219`). | Recomputed from supplied M1 bars; merge may select max time and union reasons (`:470-472`). Caller cutoff-safe only. |
| `merged_into_zone_id`, `source_level_ids`, `source_timeframes` | Same-side geometrically compatible cluster merges, with M15 source compatibility and width cap; target earliest `first_seen_at`, then lexicographic ID. Target gets unioned source IDs/timeframes; each predecessor row becomes MERGED and points to target (`zone_registry.py:375-544`). | Sufficient to trace predecessors **within a persisted registry chain**, but Snapshot supplies no prior registry and each rebuild renumbers source levels, so no stable cross-cutoff lineage. |

### Historical reconstruction limit

`snapshot_v2.load_verified_feed` clips at the prediction market minute (`:83-98`), `build_snapshot` rejects later rows (`:340-348`), and current is last 1440 minutes (`:349-352`). This makes the frozen 19-case pipeline cutoff-safe. Direct calls to `build_zone_registry` or lower-level lifecycle helpers have **FUTURE_LEAKAGE_RISK** because they sort/filter from first_seen but never take or enforce a prediction cutoff (`zone_registry.py:547-581,609-710,925-982`). `snapshot_v2._zone_fact` rejects named future event timestamps but computes interactions from all supplied rows (`:170-199`), so it is not a standalone guard.

The exact same historical object cannot always be reconstructed: liquidity map removes a buy-side zone at the first latest close above upper and a sell-side zone below lower (`liquidity_zones.py:128-140,641-659`), then Snapshot creates a fresh registry without prior history. A raw feed can reproduce lifecycle for rows still visible at a cutoff; it does not restore dropped structures or stable predecessor chains. HTF metrics also depend on the available rolling window and can be marked history-incomplete (`zone_registry.py:925-982`).

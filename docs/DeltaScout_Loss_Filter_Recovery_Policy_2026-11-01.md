# DeltaScout filter recovery and uncertain-data policy

Local implementation, not yet deployed. The existing Telegram route was tested on 2026-11-01 with a single operator-authorized non-trading test message.
This supplements the historical `DeltaScout_Loss_Avoidance_Filter_Integration_Strategy_v0_1.md`, whose original global fail-open and circuit-breaker sections describe the previous deployed behavior.

- In veto mode a trustworthy A or B BLOCK blocks the signal. A fault in the other component does not override it. BLOCK remains effective on decision-audit failure, after repeated blocks, and if evaluation exceeds its budget. Audit failure is logged and included in the blocked-event webhook.
- If neither component produces a trustworthy BLOCK and the overall decision is unknown due to data quality or evaluation failure, block the signal and issue a `LOSS_FILTER_UNVERIFIED_BLOCKED` webhook with component statuses and reason. This is recorded as `PEAK_LOSS_FILTER_DATA_BLOCK`, distinct from an A/B rule rejection. Shadow and off modes do not suppress the signal.
- Operator-approved exception: when A is trustworthy PASS, B is UNKNOWN solely because one or two explicitly synthetic minutes occur in its contiguous 240-minute feed, and the remaining required rows are numerically valid, emit the signal with `LOSS_FILTER_UNVERIFIED_EMITTED` warning. The missing values are not fabricated and B is not declared PASS. Three or more synthetic rows or other quality faults do not qualify. A real A/B BLOCK remains effective. This policy intentionally accepts uncertainty and can permit a signal B might otherwise block; thresholds are operator choices, not validated statistical conclusions.
- A history faults do not clear on a single successful write: compare the current 24-hour archived extrema with cached timestamp, side and delta (archive precision tolerance), verify persistence, then recover. Missing archives, mismatches and ambiguous timestamps inside the window leave A untrusted. On bootstrap, match rounded archive deltas to full-precision state one-to-one to avoid duplicate extrema; unmatched cached events leave A untrusted.
- Existing local naive timestamps remain; the autumn repeated hour can still make A unknown during the affected window. This change does not migrate the feed to UTC.
- The webhook uses the existing DeltaScout webhook URL. The active n8n workflow renders `body.text`; one marked test received HTTP 200 and n8n execution 14063 completed successfully on 2026-11-01 at 15:54 UTC. This verifies the route to the Telegram node, not visual receipt on the user's device. No order or signal was sent.
